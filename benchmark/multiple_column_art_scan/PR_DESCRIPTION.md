# Support residual filters on ART-backed table scans

Today, a DuckDB table scan falls back to a sequential scan as soon as more than one single-column filter is pushed down, even when one of those filters can already use a bounded ART lookup. This change keeps the existing ART lookup as the sole candidate producer and evaluates the complete pushed-down filter set after `DataTable::Fetch` returns the candidate rows.

The implementation does not intersect multiple indexes or add a new selection framework. It reuses the thread-local `TableScanState` and `ScanFilterInfo` that are already used by regular scans, applies each filter through `ColumnSegment::FilterSelection` over one shared selection vector, and only then removes filter-only columns for the final projection. A small codec-aware admission guard limits the new multi-filter path when actual fetched segments use DICT_FSST or ZSTD; rejected candidates continue through later ARTs or Sequential Scan. This heuristic does not prevent all ordinary-codec regressions. Single-filter ART admission and residual-filter behavior remain unchanged, while transaction-local storage keeps its existing scan/filter behavior. Probing, codec admission and scan initialization run outside the index list lock. An ordered entry snapshot and entry-locked read handles preserve index lifetime, safely skipping concurrently retired entries.

Focused SQLLogicTests cover residual filtering, codec admission boundaries and mixed segments, projections and column mappings, NULL semantics, multi-batch empty output, candidate limits, fallback, transaction visibility, updates, rollback, checkpoint/restart, and synchronous/task-executor execution. On a deterministic one-million-row hot-key workload, a prepared steady-state run showed the patched default using `Index Scan` while `origin/main` used `Sequential Scan`; the runner reports both single-connection threads=1/4 and one-instance multi-connection results with CPU affinity `48-64`. Low-pass-rate wide-payload probes document the extra Fetch/materialization tradeoff, while the guarded build recovers the negative case by tightening admission. `benchmark/multiple_column_art_scan/` includes the setup SQL, parameter generation, correctness gate, CLI diagnostics, and native shared-instance runner used for reproduction.
